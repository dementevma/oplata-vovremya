## 1. Что это за проект

**«Оплата вовремя»** — ИИ-помощник для малого и среднего бизнеса по дебиторской задолженности.
Главная функция: по переписке и документам определить, **почему клиент не платит по B2B-счёту**
(нет акта, спор, нет денег, согласование, реквизиты, молчит, уже оплатил), и подсказать следующий шаг.
Вокруг этого: прогноз оплаты, черновик письма, претензия по ст. 395 ГК, сверка выписки,
прогноз кассового разрыва и подбор счетов для факторинга.

Проект участвует в соревновании **«Академия Финтеха 2026»** (ВТБ + Финансовый университет),
трек **«Финтех без границ: банк будущего для бизнеса и клиентов»**. Позиционирование для ВТБ:
бесплатная функция в интернет-банке для МСБ, которая удерживает обороты на счёте и приводит
клиентов в факторинг. Подробности — `docs/00_hackathon.md`.

Команда: Иван Сороковых (ВШЭ, «Финансовые рынки и финансовые институты») — капитан, продукт и разработка;
Михаил Дементьев (GitHub `dementevma`, инженер в энергетической отрасли) — разработка, исследование, питч.

**Нельзя менять идею проекта**: дорабатывается проект из заявки.

## 4. Как запустить

```bash
npm start            # статическое демо: http://127.0.0.1:4173
npm test             # тесты логики (Node 20+)
pip install -r requirements.txt
python -m pytest tests -q
python -m server.app # живой режим с моделями: http://127.0.0.1:8000 (нужен .env)
python -m pipeline.build_demo --reuse-letters   # пересобрать демо, письма взять из прошлой сборки
python -m pipeline.build_demo   # пересобрать с новыми письмами (нужен GIGACHAT_CA_BUNDLE, см. .env.example)
python tools/survey_results.py <выгрузка Яндекс Форм> --paid 100  # итоги опроса в docs/research/custdev и на слайд 5
python tools/build_finmodel.py  # пересобрать docs/finance/financial_model.xlsx
python tools/build_deck.py  # презентация спринта 1: «ПРЕЗЕНТАЦИЯ ОПЛАТА ВОВРЕМЯ.pptx», текст питча docs/pitch_script.md
```

Ключи: скопируй `.env.example` в `.env`. Значения ключей Иван передаёт отдельно (файл `ключи_для_Миши.env`).
**Никогда не коммить `.env` и ключи.** Демо на GitHub Pages ключей не содержит: ответы моделей
сохранены в `web/data/*.json`.

## 5. Модели и как мы их используем

- **Jev** (TypeSafe, System One API, `jev-1.13.0`) — калиброванная decision-модель. На вход: текст (state)
  и атомарные вопросы трёх типов: `noul` (да/нет → вероятность), `choice` (варианты задаются словарём
  `criteria: {key: описание}`), `score` (шкала `criteria: [..]`). Возвращает вероятности. Вопросы — на
  английском, текст — любой. Время ответа ~1,3 с. См. `pipeline/causes.py`, `pipeline/clients.py`.
- **GigaChat-2** (Сбер) — только черновики писем и извлечение «что просит клиент». Каждое число в письме
  проверяется валидатором (`validate_letter`): если его нет в счёте и переписке — интерфейс предупреждает.
  ПДн (телефон, почта, паспорт, СНИЛС) маскируются до отправки в модель (`mask_pii`).
- **Правила** (`web/js/rules.js`) — базовая линия и работа без сети/ключей. Важно: в JS `\w` и `\b`
  не работают с кириллицей — используй `[а-яё]` и `(?![а-яё])`.
- **Прогноз оплаты** — логистическая (заплатит ли) + логнормальная (когда) модели, обучены на **синтетике**.
  Веса в JSON, считаются в браузере. На реальных данных нужно переобучить.

Принцип, который защищаем перед жюри: **ИИ только там, где без него нельзя** (понять смысл письма,
написать черновик). Суммы, сроки, проценты, сверка — обычный проверяемый код. Человек подтверждает
каждое внешнее действие.

## 6. Текущее качество (на 28.10.2026)

- Jev, причина по одному письму: 42/42 на ручных и 47/47 на сгенерированных GigaChat письмах (синтетика команды, не оценка точности);
  правила — 73/89 (82%). Ответ «причина не названа» засчитывается как класс «молчит».
- Jev, причина по всей истории счёта: 20/20 демо-счетов, включая ловушки (отрицание, устаревший сигнал).
- Письма GigaChat: 17/20 прошли проверки. В 1 модель выдумала «до 17:00», в 2 перепутала стороны (просит клиента прислать УПД и счёт-фактуру) — проверки поймали, вместо них шаблон.
- Прогноз (синтетика): AUC 0,88 при потолке генератора 0,88 — модель восстанавливает наши допущения; в «другом мире» 0,70. Это проверка конвейера, не качество (`pipeline/honest_eval.py`).
- **Честное ограничение**: всё синтетическое. Реальная точность — только после пилота на обезличенной переписке.
  Правила дважды исправлялись после первого прогона на выборке (баг с кириллическими `\b`/`\w`) — это
  записано в `docs/product/05_evidence_register.md`.

## 7. Правила работы в репозитории

- Пиши по-русски в интерфейсе и документах. Без длинных тире в тексте анкеты (просьба капитана).
- Не выдумывай цифры. Каждая цифра в презентации — в `docs/product/05_evidence_register.md` со статусом.
  Вендорские заявления (−30% DSO и т.п.) — только с пометкой «(вендор)», не как наш прогноз.
- Не используй логотипы и фирменный стиль ВТБ в демо (мы не ВТБ). Текстом «сценарий для ВТБ Бизнес» — можно.
- Зарубежные облачные LLM — нельзя (152-ФЗ). Только GigaChat/YandexGPT/on-prem (T-Pro, Qwen3, GigaChat 3 Lightning).
- После изменения `pipeline/demo_source.py` запусти `python -m pipeline.build_demo --reuse-letters` и `npm test`.
- Демо-ИНН могут совпасть с настоящими компаниями: не запрашивай по ним ЕГРЮЛ и не показывай результат рядом с демо-компанией.
- Демо публикуется GitHub Pages из корня ветки `main`: всё в `index.html` и `web/` должно работать
  без сборки и без сервера API.
