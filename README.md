# Оплата вовремя

**ИИ-помощник для бизнеса: почему клиент не платит по счёту и что сделать, чтобы получить деньги.**

Академия Финтеха 2026 · трек ВТБ «Финтех без границ: банк будущего для бизнеса и клиентов».

**[Открыть демо →](https://dementevma.github.io/oplata-vovremya/)** работает в браузере, без установки и регистрации.

---

## Проблема

Просроченная дебиторка российских компаний — **9 трлн ₽** (май 2026), 40% компаний называют неплатежи
главным ограничением (РСПП). Список долгов есть в любой учётной системе, но он не говорит, **почему** клиент
не платит. А причины разные: ждёт исправленный УПД, спорит о сумме, платёж стоит на согласовании,
банк вернул деньги из-за опечатки в реквизитах, уже заплатил — или правда нет денег. Каждой причине нужно
своё действие. Сейчас бухгалтер ищет ответ в почте и шлёт всем одинаковые напоминания.

## Что делает продукт

| Экран | Что видит пользователь |
|---|---|
| **Сегодня** | очередь действий по деньгам под риском, причины просрочки, прогноз поступлений и кассового разрыва |
| **Письмо** | вставьте ответ клиента: причина и следующий шаг без реестра и подключений |
| **Документ** | проверка счёта, акта или УПД до отправки: контрольные суммы реквизитов, сумма и стороны, актуальный КПП |
| **Счета → карточка** | причина с вероятностями и цитатой-основанием, следующий шаг, прогноз оплаты, письмо с проверкой фактов, платёжный QR по ГОСТ, процедура и госпошлина, претензия по ст. 395 ГК |
| **Сверка выписки** | платежи из файла 1С: Клиент-банк сопоставлены со счетами, каждое совпадение объяснено |
| **Деньги сейчас** | остаток на 8 недель, неделя разрыва, счета для факторинга, цена денег, реестр уступки с согласием клиента |
| **Качество ИИ** | матрицы ошибок Jev и правил на размеченных письмах, проверка писем, калибровка прогноза |
| **Для банка** | что видит ВТБ: дебиторка клиентов МСБ, кандидаты на факторинг, ранние сигналы риска |

Попробуйте в демо: счёт **1069** (клиент сначала просил акт, а потом написал, что банк заморозил кредитную
линию — модель не ловится на устаревший сигнал), счёт **1067** («деньги есть, дело не в этом» — согласование),
письмо по счёту **1066** (валидатор ловит выдуманное моделью «до 17:00»), сверку платежа **7781** (два счёта одним
платежом), переключатель **«Работать без ИИ»**.

## Как устроен ИИ

```
переписка + документы + выписка
        │
        ├─► Jev (decision-модель, вероятности на атомарные вопросы) ─► причина, признаки, цитата
        │        └ без сети: правила в браузере
        ├─► прогноз оплаты (логистическая + логнормальная модели, веса в браузере)
        ├─► таблица решений ─► следующий шаг (при споре — пауза напоминаний)
        ├─► GigaChat ─► черновик письма ─► валидатор: каждое число есть в данных? ─► человек отправляет
        └─► обычный код: сверка, проценты ст. 395, кассовый поток, факторинг, претензия
```

ИИ только там, где без него нельзя: понять смысл письма и написать черновик. Генеративная модель российская,
ПДн маскируются до отправки, в банке всё разворачивается on-prem. Подробно — [`docs/product/04_pilot_security.md`](docs/product/04_pilot_security.md).

### Качество (синтетические данные, честно)

| Что | Результат |
|---|---|
| Jev: причина по письму, письма команды с трудными формулировками | 42/42 |
| Jev: причина по письму, письма, сгенерированные GigaChat | 47/47 |
| Правила без ИИ, тот же набор | 73/89 (82%) |
| Jev: причина по всей истории счёта (20 демо-счетов с ловушками) | 20/20 |
| Письма GigaChat без ошибок | 17/20: одно выдуманное число и два письма с перепутанными сторонами пойманы проверками |
| Jev, 95% доверительный интервал по 89 письмам | 96–100% на наших письмах |
| Обучаемый бейзлайн (TF-IDF + логистическая регрессия), кросс-валидация | 61%; обучен на GigaChat, проверен на ручных: 40% |
| Прогноз оплаты: AUC модели / потолок генератора / в «другом мире» | 0,88 / 0,88 / 0,70 — проверка конвейера, не качество |

**Это не оценка точности.** Все письма синтетические: их написала команда или сгенерировал GigaChat, независимой отложенной выборки пока нет. 100% значит, что модель понимает наши формулировки, а не что она не ошибается. Реальную точность измерим на обезличенной переписке пилота (цель — macro-F1 не ниже 0,75; нужно ~200 размеченных писем). Как получены цифры — `python -m pipeline.honest_eval`.

## Запуск

```bash
npm start                     # демо: http://127.0.0.1:4173
npm test                      # 28 тестов логики
pip install -r requirements.txt
python -m pytest tests -q     # 23 теста Python
cp .env.example .env          # ключи Jev и GigaChat
python -m server.app          # живой режим с моделями: http://127.0.0.1:8000
python -m pipeline.build_eval # пересобрать оценочную выборку
python -m pipeline.build_demo # пересобрать ответы моделей для демо
python -m pipeline.forecast   # переобучить прогноз
python tools/build_finmodel.py
```

## Ограничения

Компании, суммы и переписка в демо вымышлены. Ответы Jev и GigaChat для демо получены заранее и сохранены
в `web/data/` — ключи в репозитории не хранятся. Сведения из реестров (ФНС, Федресурс, суды) в демо заданы
вручную. Прогноз обучен на синтетике. Пользовательских интервью и пилота пока не было. Сервис не проводит
платежи и ничего не отправляет сам.
